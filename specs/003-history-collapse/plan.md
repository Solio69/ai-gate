# Implementation Plan: Сворачивание карточек истории

**Branch**: `main` | **Date**: 2026-10-22 | **Spec**: [spec.md](spec.md)

**Input**: карточка истории в свёрнутом виде показывает только заголовок запроса и кнопку справа; раскрытие показывает полный Markdown и дату.

## Summary

Убрать текстовый предпросмотр, обрезающий Markdown на 180 символах. Каждая карточка стартует свёрнутой; в заголовке рядом с запросом всегда есть кнопка. Ответ через существующий `ReactMarkdown` и время рендерятся только в раскрытом состоянии. Состояние остаётся независимым для каждой карточки и не сохраняется.

## Technical Context

**Language/Version**: TypeScript, Node.js 24+, React 19

**Primary Dependencies**: существующие React, `react-markdown`, Vite; новых зависимостей нет

**Storage**: прежние `localStorage` и PostgreSQL без изменения схемы или формата

**Testing**: Vitest и React Testing Library в `apps/web/test/App.test.tsx`

**Target Platform**: браузер в локальном Vite и на Vercel

**Project Type**: npm workspaces `apps/web` и `apps/api`

**Performance Goals**: история остаётся читаемой при нескольких длинных ответах

**Constraints**: без API/БД изменений; полный ответ сохраняется без сокращения; сырой HTML по-прежнему не исполняется

**Scale/Scope**: одна существующая карточка интерфейса и связанные тесты/документы

## Constitution Check

- **Минимальный объём**: только согласованное отображение истории; форма, текущий ответ и сохранение не меняются.
- **Секреты и сессия**: ключи и cookie не затрагиваются; локальная история остаётся привязанной к прежнему ID сессии.
- **Тесты до поведения**: сначала изменяются браузерные тесты и получается осмысленный Red, затем код и Green.
- **Понятная документация**: обновляются `docs/03-history.md`, `docs/README.md` и README без изменения описания других фич.
- **Проверка запуска**: применимые тесты, типизация и сборка фиксируются в `verification.md`; ручной опубликованный сценарий помечается отдельно по факту.

Повторная проверка после проектирования: новые зависимости, данные или контракты не нужны; нарушений конституции не выявлено.

## Phase 0: Research

[Сравнение вариантов](research.md) показало, что скрытие ответа до раскрытия соответствует согласованному виду и устраняет показ обрезанной разметки. CSS-обрезка отформатированного содержания не нужна.

## Phase 1: Design & Contracts

- Визуальная структура карточки: строка «заголовок запроса — кнопка»; тело с полным Markdown и датой только при `expanded=true`.
- Кнопка всегда доступна, меняет текст «Развернуть»/«Свернуть» и значение `aria-expanded`.
- Длинный запрос переносится без выхода из карточки; кнопка остаётся доступной на узком экране.
- [Ручная проверка](quickstart.md) описывает вид списка до/после раскрытия и после обновления.
- Модель данных и HTTP-контракты не меняются, поэтому новые `data-model.md` и `contracts/` не создаются.

## Test-first and verification plan

1. **Red**: изменить `apps/web/test/App.test.tsx`, чтобы короткий и длинный ответы были скрыты до нажатия; проверить кнопку напротив заголовка, дату только после раскрытия, форматирование Markdown, независимость двух карточек и свёрнутое состояние после reload. Выполнить `npm run test -w apps/web -- App.test.tsx`; требуемый Red — падение утверждений из-за текущего текстового предпросмотра/отсутствующей кнопки у короткого ответа, а не ошибка установки или импорта.
2. **Green**: в `apps/web/src/App.tsx` удалить ветку предпросмотра; всегда показывать кнопку и условно рендерить полный ответ и дату. В `apps/web/src/styles.css` разместить запрос и кнопку напротив друг друга. Повторить целевой тест.
3. **Refactor**: убрать неиспользуемые константу длины и CSS предпросмотра; сохранить доступный `aria-expanded` и перенос длинного запроса. Повторить затронутые тесты.
4. **Итог**: `npm run test -w apps/web`, `npm run typecheck -w apps/web`, `npm run build -w apps/web`, `git diff --check`; проверить отсутствие секретов и посторонних изменений. Документацию проверить чтением и поиском устаревших формулировок о 180 символах. Ручной опубликованный сценарий не считать Passed до фактического просмотра после push. Не запускать пользовательские dev-серверы за неё.

Проверки и их реальные статусы записать в `verification.md`. Новая тестовая зависимость не требуется; серверные тесты не повторяются, потому что API и хранилище не меняются.
