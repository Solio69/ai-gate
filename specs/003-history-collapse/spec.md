# Feature Specification: Сворачивание карточек истории до заголовка запроса

**Feature Branch**: `main` (согласовано пользователем)

**Created**: 2026-10-22

**Status**: Implemented

**Input**: В свёрнутой истории не показывать обрезанный сырой Markdown; оставлять заголовок запроса и кнопку справа, по которой раскрывается полный ответ.

## Agreed scope and decision boundaries

**Результат:** каждая завершённая пара в истории сначала занимает одну карточку с текстом запроса и кнопкой «Развернуть» напротив. По нажатию показываются полный ответ с Markdown и дата; кнопка меняется на «Свернуть».

**В объёме:** одинаковое сворачивание коротких и длинных ответов; независимое управление карточками; свёрнутое состояние при новом открытии страницы; обновление тестов и русскоязычной документации истории.

**За пределами:** изменение формы, текущего потокового ответа, API, модели данных, PostgreSQL, формата `localStorage`, содержимого сохранённых ответов и серверного чтения истории.

**Приёмка:** свёрнутая карточка не показывает ответ, фрагмент Markdown или дату; кнопка расположена напротив заголовка запроса. После раскрытия полный ответ отображается как Markdown и видна дата; повторное нажатие снова скрывает их. Короткий ответ ведёт себя так же, как длинный. Обновление страницы сохраняет пары, но показывает карточки свёрнутыми.

**Открытые решения:** нет.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Читать историю без обрывков Markdown (Priority: P1)

Посетитель видит компактный список запросов. Он раскрывает нужный запрос и читает полный ответ с сохранённой разметкой.

**Why this priority**: текущая текстовая обрезка показывает символы Markdown вместо читаемого содержания и загромождает историю.

**Independent Test**: подготовить в локальной истории короткий и длинный ответы, в том числе с Markdown-заголовком; проверить начальное состояние и раскрытие каждой карточки.

**Acceptance Scenarios**:

1. **Given** завершённая пара с коротким или длинным ответом, **When** история открыта, **Then** видны только заголовок запроса и кнопка «Развернуть» справа; ответ и дата скрыты.
2. **Given** свёрнутая карточка с Markdown в ответе, **When** нажата «Развернуть», **Then** полный ответ отображается отформатированным и дата видна.
3. **Given** раскрытая карточка, **When** нажата «Свернуть», **Then** ответ и дата скрываются без изменения сохранённой пары.

### User Story 2 - Управлять карточками независимо (Priority: P2)

Посетитель раскрывает только интересующие его запросы. После обновления страницы видит сохранённые пары снова свёрнутыми.

**Why this priority**: историю из нескольких ответов должно быть удобно просматривать без раскрытия всего списка.

**Independent Test**: подготовить две пары, раскрыть одну, проверить вторую, обновить страницу и повторно открыть историю.

**Acceptance Scenarios**:

1. **Given** две свёрнутые карточки, **When** раскрыта одна, **Then** вторая остаётся свёрнутой.
2. **Given** раскрытая карточка и сохранённая история, **When** страница обновлена, **Then** пара остаётся в истории, а карточка снова свёрнута.

### Edge Cases

- Длинный текст запроса переносится в пределах карточки; кнопка остаётся доступной.
- Даже короткий ответ имеет кнопку раскрытия и не показывается до нажатия.
- Сырой HTML внутри ответа остаётся заблокированным существующим Markdown-рендерером.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Каждая карточка истории MUST быть свёрнутой при первом отображении независимо от длины ответа.
- **FR-002**: В свёрнутой карточке MUST отображаться только заголовок запроса и расположенная напротив него кнопка раскрытия; ответ и дата MUST быть скрыты.
- **FR-003**: При раскрытии карточки MUST отображаться полный ответ через существующий Markdown-рендерер и дата сохранённой пары.
- **FR-004**: Повторное нажатие MUST скрывать ответ и дату; состояние одной карточки MUST NOT менять состояние других.
- **FR-005**: После обновления страницы сохранённые пары MUST оставаться в истории, а их карточки MUST возвращаться в свёрнутое состояние.
- **FR-006**: Изменение отображения MUST NOT менять содержимое пар, формат хранения и серверное поведение.

### Key Entities

- **Сохранённая пара**: прежние ID, запрос, полный ответ, время и ID анонимной сессии; структура не меняется.
- **Состояние карточки**: временный признак раскрытия в интерфейсе; в хранилище не записывается.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Для короткого и длинного ответа начальная карточка содержит 0 символов ответа и не показывает дату.
- **SC-002**: После одного нажатия весь Markdown-ответ виден как отформатированный текст; обрезанного сырого фрагмента нет.
- **SC-003**: При раскрытии одной из двух карточек вторая остаётся свёрнутой.
- **SC-004**: После обновления страницы сохранённые карточки доступны и свёрнуты по умолчанию.
- **SC-005**: Применимые тесты интерфейса, типизация и сборка проходят.

## Assumptions

- История по-прежнему берётся из `localStorage` текущей анонимной сессии.
- Существующий `react-markdown` остаётся средством показа полного ответа; новых зависимостей не нужно.
- Состояние раскрытия живёт только до размонтирования карточки или обновления страницы.
