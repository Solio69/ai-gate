# Research: сворачивание истории

## Текущее поведение

`HistoryItem` в `apps/web/src/App.tsx` делит ответы по длине 180 Unicode-символов. Длинный ответ режется до рендера Markdown и показывается как обычный текст, поэтому в списке видны `###`, `**` и незакрытые конструкции. Короткий ответ показывается целиком без кнопки. Время видно всегда. Сохранение в `localStorage` и PostgreSQL не связано с этой обрезкой.

## Варианты

1. **Скрыть ответ целиком до раскрытия (выбрано)**. В карточке остаются заголовок запроса и кнопка. Раскрытая карточка использует уже установленный `react-markdown`; дата видна вместе с ответом. Преимущества: нет обрезанного Markdown, единое поведение для всех ответов, минимальная правка без зависимости.
2. Обрезать уже отрисованный Markdown средствами CSS. Это оставило бы предпросмотр, но могло бы визуально отсечь пункт списка, таблицу или блок кода; также не соответствует согласованному виду «до заголовка».

## Решение

Использовать первый вариант. Признак раскрытия остаётся локальным состоянием каждой карточки. В хранилище записывается прежняя полная пара. Кнопка должна иметь понятный текст и `aria-expanded`; заголовок и кнопка располагаются в одной строке с переносом длинного запроса. Новых библиотек, API и миграций нет.
