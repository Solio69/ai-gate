# Feature Specification: Минимальный AI Gate

**Feature Branch**: `main`

**Created**: 2026-10-22

**Status**: Согласовано

**Input**: Минимальное тестовое приложение с анонимной сессией, потоковым ответом
бесплатной модели, локальной историей браузера и серверной историей по сессиям.

## Agreed scope and decision boundaries

**Результат:** человек без регистрации отправляет запрос и видит ответ по мере
появления. Завершённая пара запрос–ответ доступна в локальной истории, а на
сервере хранится с привязкой к анонимной сессии.

**В объёме:** форма до 500 символов; потоковый ответ; понятные состояния ожидания
и ошибки; локальная история после обновления страницы; серверная запись истории;
документация фич и README для проверки архитектуры и результата; проверенный локальный запуск; коммит в `main`.

**Вне объёма текущего этапа:** регистрация, платные модели, передача всей прошлой
истории модели как контекста, чтение серверной истории в интерфейс и публикация.

**Критерии приёмки:** один корректный запрос показывает ответ постепенно; пустой
или слишком длинный запрос отклоняется; завершённый ответ появляется в локальной
истории после обновления; сервер сохраняет пару под ID текущей сессии; разные
сессии не смешиваются; проект запускается локально по инструкции.

**Открытые решения:** конкретный ID бесплатной модели выбирается при планировании
по актуальной документации провайдера и остаётся настраиваемым.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Получить потоковый ответ без регистрации (Priority: P1)

Посетитель открывает страницу, видит форму, вводит короткий запрос и отправляет
его. Ответ появляется частями, затем остаётся целиком. Логин не требуется.

**Why this priority**: Это основной демонстрируемый сценарий тестового задания.

**Independent Test**: В чистом браузере отправить запрос и увидеть первые части
ответа до завершения генерации, затем полный ответ.

**Acceptance Scenarios**:

1. **Given** открыта форма, **When** посетитель вводит от 1 до 500 значимых
   символов и отправляет запрос, **Then** видит постепенно дополняемый ответ.
2. **Given** пустая форма или только пробелы, **When** посетитель пытается
   отправить запрос, **Then** отправка не происходит и показана причина.
3. **Given** запрос длиннее 500 символов, **When** он отправлен, **Then** сервис
   отклоняет его и не обращается к модели.
4. **Given** внешний сервис прервал ответ, **When** поток завершился ошибкой,
   **Then** посетитель видит ошибку, а частичный текст не помечается завершённым.
5. **Given** введён допустимый запрос, **When** посетитель нажимает Enter без Shift,
   **Then** форма отправляет запрос один раз; Shift+Enter вставляет новую строку.
6. **Given** запрос отправлен, **When** получен успешный ответ, **Then** исходный
   текст очищается из поля. При ошибке текст остаётся для повтора; новый текст,
   введённый во время ответа, не удаляется.
7. **Given** ответ содержит базовый Markdown, **When** текст поступает частями или завершён,
   **Then** форматирование видно в текущем ответе без выполнения HTML из ответа.

---

### User Story 2 - Видеть локальную историю (Priority: P2)

После успешного ответа посетитель видит пару запрос–ответ в списке истории.
При обновлении страницы история текущей анонимной сессии остаётся видимой.

**Why this priority**: Локальная история прямо указана в задании.

**Independent Test**: Получить завершённый ответ, обновить страницу и увидеть
ту же пару; открыть новую сессию и убедиться, что чужая история не показана.

**Acceptance Scenarios**:

1. **Given** ответ завершён, **When** страница обновлена, **Then** пара
   запрос–ответ снова видна в локальной истории.
2. **Given** ответ завершился ошибкой, **When** страница обновлена, **Then**
   частичный ответ не показан как успешная запись истории.
3. **Given** создана другая анонимная сессия, **When** открыта форма, **Then**
   локальная история прежней сессии ей не показывается.
4. **Given** в истории есть ответ длиннее 180 Unicode-символов, **When**
   история открывается, **Then** виден сокращённый ответ с многоточием.
   Посетитель может раскрыть его полностью и снова свернуть; после обновления
   страницы ответ снова свёрнут.

---

### User Story 3 - Сохранить историю по анонимной сессии (Priority: P3)

После завершения ответа сервис сохраняет запрос и полный ответ под анонимным
идентификатором сессии. Регистрация и профиль пользователя не нужны.

**Why this priority**: Это подтверждает требование о серверной истории по сессиям.

**Independent Test**: Отправить запросы в двух сессиях и проверить, что записи
содержат два разных ID сессии и соответствующие пары.

**Acceptance Scenarios**:

1. **Given** ответ завершён успешно, **When** сервис фиксирует результат,
   **Then** для текущей сессии создана ровно одна запись с запросом и полным
   ответом.
2. **Given** два независимых посетителя, **When** каждый получил ответ,
   **Then** их записи относятся к разным анонимным сессиям.
3. **Given** генерация или сохранение завершились ошибкой, **When** сервис
   сообщает результат, **Then** неполная пара не сохранена как успешная.

### Edge Cases

- У посетителя нет ранее выданной сессии: сервис создаёт новую автоматически.
- Ранее выданная сессия повреждена или устарела: сервис создаёт новую, не
  показывая локальную историю другой сессии.
- Ответ модели пустой или поток оборвался: сервис показывает ошибку и не
  сохраняет пустую успешную пару.
- Серверное хранилище недоступно после генерации: посетитель видит ошибку;
  локальная история не получает запись, представленную как успешно сохранённую.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Посетитель MUST получать доступ к форме без регистрации.
- **FR-002**: Сервис MUST автоматически назначать анонимную сессию и отличать
  записи разных сессий.
- **FR-003**: Форма и сервис MUST принимать непустой запрос длиной не более
  500 символов и отклонять остальные.
- **FR-004**: Посетитель MUST видеть ответ частями по мере генерации.
- **FR-005**: Посетитель MUST видеть понятное состояние ошибки при сбое
  генерации или сохранения.
- **FR-006**: После успешного завершения сервис MUST сохранить одну пару
  запрос–полный ответ под ID текущей анонимной сессии.
- **FR-007**: Сервис MUST сохранять завершённые пары в локальной истории
  браузера и восстанавливать её после обновления страницы в той же сессии.
- **FR-008**: Новая анонимная сессия MUST NOT показывать локальную историю
  предыдущей сессии.
- **FR-009**: Секрет доступа к модели и реквизиты серверного хранилища MUST NOT
  передаваться в браузер.
- **FR-010**: Форма MUST отправлять запрос по Enter без Shift и оставлять
  возможность ввода новой строки по Shift+Enter; во время текущего запроса
  повторная отправка MUST NOT происходить.
- **FR-011**: После успешного ответа форма MUST очищать отправленный текст,
  если поле не изменялось. При ошибке и вводе нового текста во время ответа
  текущий текст MUST сохраняться.
- **FR-012**: История MUST показывать ответы длиннее 180 Unicode-символов
  сокращёнными с многоточием и давать раскрыть/свернуть полный текст.
  Изначально длинный ответ MUST быть свёрнутым.
- **FR-013**: Текущий ответ и раскрытая запись истории MUST отображать базовый
  Markdown (заголовки, акценты, списки, ссылки и код) без выполнения сырого HTML.
  Сокращённый предпросмотр истории остаётся обычным текстом.

### Key Entities *(include if feature involves data)*

- **Анонимная сессия**: случайный идентификатор посещения без аккаунта.
- **Запись истории**: запрос, полный ответ, время и идентификатор сессии.
- **Локальная история**: доступный текущей сессии список завершённых записей
  в браузере.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Один посетитель может отправить допустимый запрос и увидеть
  первые части ответа до получения полного текста.
- **SC-002**: Запросы длиной 0 и 501 символ отклоняются; запрос длиной 500
  символов принимается.
- **SC-003**: После обновления страницы 100% завершённых записей текущей
  сессии, сохранённых локально, снова видны.
- **SC-004**: Для каждого успешного запроса создаётся ровно одна серверная
  запись, содержащая полный ответ и ID текущей сессии.
- **SC-005**: При проверке двух независимых сессий их записи имеют разные
  идентификаторы и не смешиваются в локальном интерфейсе.
- **SC-006**: Enter отправляет один запрос, Shift+Enter не отправляет; после
  успешного ответа поле пустое, после ошибки исходный текст доступен повторно.
- **SC-007**: Длинный ответ в истории изначально сокращён и раскрывается
  полностью по действию пользователя; после reload он снова свёрнут.
- **SC-008**: Markdown-разметка текущего и раскрытого исторического ответа
  отображается как структурированный текст, а HTML из ответа не выполняется.

## Assumptions

- Для локального сценария есть интернет и доступ к бесплатной модели через
  имеющийся у пользователя ключ провайдера.
- История нужна для показа и хранения; передача её модели как контекста не
  заявлена.
- В текущем этапе проверяется локальный запуск; ссылка на опубликованный
  сервис появится отдельным этапом после проверки пользователем.
