# Модель данных

## Анонимная сессия

Сервер создаёт случайный UUID и помещает его в подписанную cookie `ai_gate_session`. Отдельной таблицы сессий нет: ID повторяется в записях истории. Сервер принимает ID для доступа к записи только из корректно подписанной cookie. `GET /api/session` отдаёт ID браузеру исключительно для выбора собственного ключа локальной истории; параметр `sessionId` от клиента в `POST /api/chat` не принимается.

## Запись истории `exchanges`

| Поле | Тип PostgreSQL | Назначение |
|---|---|---|
| `id` | `uuid PRIMARY KEY DEFAULT gen_random_uuid()` | ID одной завершённой пары |
| `session_id` | `uuid NOT NULL` | ID анонимной сессии |
| `prompt` | `text NOT NULL` | Обрезанный по краям запрос пользователя |
| `answer` | `text NOT NULL` | Полный ответ после завершения потока |
| `created_at` | `timestamptz NOT NULL DEFAULT now()` | Время успешной записи |

Индекс `(session_id, created_at, id)` ускоряет выборку и упорядочивание пар одной сессии, если позже понадобится чтение истории из БД.

### Инварианты

- `prompt` содержит от 1 до 500 символов после `trim`; одинаковое правило действует на клиенте и сервере. Длина считается по Unicode code points, чтобы один emoji не занимал два символа в интерфейсе.
- `answer` не пустой. Частичный или оборванный поток не создаёт запись.
- Один успешно завершённый запрос создаёт ровно одну строку.
- Два независимых посетителя получают разные `session_id`; общей таблицы пользователей нет.
- Секреты OpenRouter, БД и подписи cookie не попадают в таблицу.

## Локальная история

Браузер хранит массив завершённых записей под ключом `ai-gate:history:<sessionId>`. Поля записи соответствуют ответу события `done`: `id`, `prompt`, `answer`, `createdAt`. `sessionId` задаёт пространство имён, но сам по себе не даёт доступа к чужим серверным данным. Для новой или повреждённой cookie сервер создаёт новый ID, поэтому браузер выбирает другой ключ и не показывает записи старой сессии.

## Состояния одного запроса

`idle → streaming → persisted` после успешной записи в БД и события `done`.

Из `streaming` возможен переход в `failed` при ошибке провайдера, обрыве потока, пустом ответе или ошибке БД. В `failed` неполная пара не попадает ни в PostgreSQL, ни в локальную историю как завершённая.
