**Входные документы**: `spec.md`, `plan.md`, `research.md`, `data-model.md`, `contracts/api.md`, `quickstart.md` в `specs/001-ai-gate-demo/`.

**Принцип выполнения**: для проверяемого поведения сначала осмысленный падающий тест (Red), затем минимальная реализация (Green), затем упрощение без изменения поведения (Refactor). Ошибка установки пакета, импорта или Docker не считается Red. Ветка Git остаётся `main`; публикация относится к следующему этапу после локальной проверки пользователем.

## Phase 4: US2 — локальная история текущей сессии (P2)

**Цель:** завершённая пара остаётся в браузере после обновления страницы, а новая сессия не видит историю прежней.

**Независимая проверка:** `done` добавляет запись, ошибка и обрыв не добавляют; reload с тем же `sessionId` показывает запись, новый `sessionId` выбирает другой ключ.

## Phase 5: US3 — PostgreSQL-история по анонимной сессии (P3)

**Цель:** каждый успешный запрос создаёт ровно одну полную запись с ID cookie-сессии; ошибка не создаёт успешную запись.

**Независимая проверка:** с тестовой PostgreSQL и подменённым upstream отправить запросы из двух cookie-сессий, затем проверить две строки с разными `session_id`. При ошибке вставки не должно быть `done` или локальной успешной истории.

- T007 и T008 независимы после T006. T009/T011 относятся к API, T010/T012 — к UI; внутри каждой пары Red всегда раньше зависимого Green. T014/T016 и T015/T017 аналогично разделяют потоковую часть.
- US1 завершается после T018. US2 (T019–T021) и US3 (T022–T024) могут выполняться параллельно после US1, поскольку первая меняет браузерный код, вторая — API/БД.
- T025 и T026 могут выполняться параллельно после основных фич; T027–T029 требуют завершения реализации и документации.

## Parallel execution examples

- После T006 один исполнитель готовит API-заглушки T007, другой — React-заглушки T008.
- После T008/T007 тесты T009 и T010 пишутся параллельно; реализации T011 и T012 начинаются только после собственного Red.
- В потоковой части API-тест T014 и UI-тест T015 независимы; T016 и T017 реализуются по своим тестам, затем вместе сверяются контрактом.
- После US1 браузерная история T019–T021 и PostgreSQL T022–T024 могут идти у разных исполнителей без одновременного изменения одних файлов.

## Implementation strategy and completion criteria

Первый демонстрируемый инкремент — US1: анонимная форма и видимый поток с подменённым хранилищем. Затем US2 добавляет локальную историю, US3 — реальную PostgreSQL. Окончательный результат определяется всеми тремя историями и локальной проверкой, а не только первым инкрементом.

- Каждый проверяемый сценарий имеет зафиксированный настоящий Red до production-кода и повторный Green после него.
- После Refactor все затронутые тесты проходят; ошибки установки не выдаются за Red.
- `analysis.md` содержит полный отдельный отчёт без нерешённых блокирующих находок.
- `verification.md` честно различает выполненные, проваленные и недоступные проверки.
- Документация и код соответствуют согласованной спецификации; коммит выполняется в `main` только по разрешённым путям.
