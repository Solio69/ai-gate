# Локальный запуск и проверка

Этот сценарий рассчитан на Windows PowerShell, Node.js 24, npm и Docker Desktop. Команды ниже относятся к проекту после реализации задач по [`plan.md`](plan.md). Публикация на Vercel в текущий этап не входит.

## Подготовка

1. Откройте PowerShell в корне репозитория.
2. Создайте локальный файл окружения: `Copy-Item .env.example .env`.
3. Впишите **свой** `OPENROUTER_API_KEY` в `.env`. Оставьте `OPENROUTER_MODEL=openrouter/free` или задайте доступную бесплатную модель. В `.env` также должны быть `DATABASE_URL` и `COOKIE_SECRET` согласно примеру. Замените демонстрационное значение `COOKIE_SECRET` случайным секретом перед запуском. Файл `.env` игнорируется Git; ключ не отправляйте в чат и не выводите в логи.
4. Запустите Docker Desktop, затем базу: `docker compose up -d db`. При первом создании volume SQL-инициализация создаст таблицу `exchanges`.
5. Установите зависимости: `npm ci`.

## Запуск приложения

В первом терминале выполните `npm run dev -w apps/api`, во втором — `npm run dev -w apps/web`. Откройте `http://127.0.0.1:5173`. Vite передаёт запросы `/api` серверу Express на `http://127.0.0.1:3001`, поэтому браузер работает с одним origin и cookie-сессия не требует отдельной CORS-настройки.

## Ручная проверка

1. Откройте страницу в обычном окне: форма доступна без входа.
2. Отправьте короткий запрос. Ответ должен появляться частями, затем остаться целиком.
3. Обновите страницу: завершённая пара должна остаться в локальной истории.
4. Отправьте пустой запрос и запрос длиной 501 символ: сервис должен показать причину отказа без обращения к модели.
5. Откройте страницу в новом окне инкогнито: старая локальная история там не показывается. Отправьте другой запрос.
6. Проверьте БД. Пример для локального Compose с пользователем и БД `ai_gate`:

```powershell
docker compose exec db psql -U ai_gate -d ai_gate -c "SELECT session_id, prompt, answer, created_at FROM exchanges ORDER BY created_at;"
```

В выводе должны быть две завершённые пары с разными `session_id`. Наличие строки в БД само по себе не подтверждает стриминг — его нужно наблюдать в интерфейсе во время запроса.

## Автоматические проверки

После установки зависимостей и создания package scripts выполняются `npm test --workspaces`, `npm run typecheck --workspaces` и `npm run build --workspaces`. Если зависимость, ключ или Docker недоступны, зафиксируйте проверку как `Blocked` или `NotRun` в `verification.md`; не записывайте её как `Passed`.
