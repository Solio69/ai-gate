# Feature Specification: Публикация AI Gate на Vercel

**Feature Branch**: `main` (прямое указание пользователя)  
**Created**: 2026-10-22  
**Status**: Draft  
**Input**: Разместить готовое тестовое приложение на Vercel с рабочими потоковыми ответами и PostgreSQL, используя бесплатные тарифы.

## Agreed scope and decision boundaries

**Результат:** доступная по ссылке версия существующего AI Gate. Посетитель без регистрации отправляет запрос, видит ответ по частям и завершённую пару в истории; запись появляется в PostgreSQL.

**В объёме:** подготовка текущего монорепозитория к одному проекту Vercel, подключение доступной из интернета PostgreSQL на бесплатном тарифе, защищённая настройка секретов, инструкция и проверка опубликованного сценария. Локальный запуск сохраняется.

**За пределами:** новые функции интерфейса, изменение истории и схемы данных, платные тарифы, отдельный сервер API или собственный домен.

**Приёмка:** опубликованная ссылка открывается без локальных процессов; запрос и ответ идут потоком; успешная пара записана в БД и видна после обновления страницы в той же браузерной сессии; другая сессия не видит эту локальную историю; ключи не попадают в браузер или Git.

**Открытые решения:** конкретный ресурс PostgreSQL и значения секретов создаются в аккаунте пользователя на этапе публикации. До этого проверка опубликованной ссылки остаётся незавершённой.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Проверить приложение по ссылке (Priority: P1)

Проверяющий открывает ссылку без локальной установки, вводит запрос и наблюдает появление ответа по частям.

**Why this priority**: Это главный результат публикации тестового задания.

**Independent Test**: Открыть ссылку в новом браузере, отправить запрос и увидеть неполный ответ до его завершения.

**Acceptance Scenarios**:

1. **Given** опубликованное приложение, **When** посетитель открывает ссылку, **Then** форма доступна без регистрации.
2. **Given** корректный запрос и доступная бесплатная модель, **When** посетитель отправляет его, **Then** части ответа появляются до завершения генерации.
3. **Given** ошибка внешнего сервиса, **When** запрос завершается неуспешно, **Then** посетитель видит ошибку, а завершённая пара не появляется в истории.

### User Story 2 - Сохранить и восстановить результат (Priority: P2)

После успешного ответа посетитель видит пару в истории; завершённая пара также сохраняется на сервере.

**Why this priority**: Требование тестового задания включает PostgreSQL и историю браузера.

**Independent Test**: Отправить запрос, обновить страницу и проверить историю; затем проверить строку в PostgreSQL и независимую браузерную сессию.

**Acceptance Scenarios**:

1. **Given** завершённый ответ, **When** страница обновлена, **Then** пара остаётся в истории этой браузерной сессии.
2. **Given** завершённый ответ, **When** проверяется PostgreSQL, **Then** там есть одна полная пара с ID анонимной сессии.
3. **Given** другое окно инкогнито, **When** открывается та же ссылка, **Then** локальная история первой сессии не показывается.

### Edge Cases

- При недоступной БД ответ не считается успешно завершённым и история не пополняется.
- При исчерпании лимита бесплатной модели пользователь получает понятную ошибку.
- После смены домена локальная история с `localhost` не переносится: браузер хранит её отдельно для каждого адреса.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Приложение MUST открываться по HTTPS-ссылке без локально запущенных процессов пользователя.
- **FR-002**: Публичная версия MUST сохранять существующие форму, границу 1–500 символов и потоковое отображение ответа.
- **FR-003**: Сервер MUST хранить ключ модели, секрет cookie и адрес БД вне клиентского кода и публичного репозитория.
- **FR-004**: После успешного ответа сервер MUST сохранить полную пару в PostgreSQL под ID анонимной сессии до подтверждения успеха браузеру.
- **FR-005**: Браузер MUST восстанавливать историю текущей анонимной сессии после обновления страницы.
- **FR-006**: Локальный сценарий запуска MUST продолжить работать после подготовки к публикации.
- **FR-007**: Проект MUST содержать пошаговую инструкцию для бесплатного размещения и проверки, включая создание схемы БД и настройку секретов.

### Key Entities

- **Анонимная сессия**: идентификатор в подписанной cookie, связывает завершённые запросы.
- **Пара запроса и ответа**: полный текст запроса и ответа, ID сессии и время; схема уже определена в `001-ai-gate-demo`.
- **Локальная история**: копия завершённых пар в браузере для отображения после обновления.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: По одной ссылке проверяющий открывает форму и отправляет запрос без установки приложения.
- **SC-002**: В проверочном запросе хотя бы один фрагмент ответа виден до окончательного завершения ответа.
- **SC-003**: После успешного запроса ровно одна полная пара находится в PostgreSQL и отображается после обновления страницы в исходной браузерной сессии.
- **SC-004**: В отдельной сессии история первой сессии не показывается.
- **SC-005**: Проверки локального запуска, типизации и сборки остаются успешными.

## Assumptions

- Используются бесплатные Vercel Hobby, PostgreSQL Free и бесплатная модель OpenRouter; сервисы имеют лимиты и могут отказать при их исчерпании.
- Для опубликованной версии применяется существующая схема `exchanges`; перенос локальных демонстрационных данных не требуется.
- Пользователь выполняет действия в своём Vercel-аккаунте и не публикует секреты в чате или Git.
