# Фича 4. Локальный запуск и проверка

**Состояние:** автоматические проверки и локальный сквозной сценарий с управляемым SSE прошли; реальный запрос к OpenRouter заблокирован отсутствующим ключом.

## Что подготовлено

Проект разделён на два npm workspace: React-интерфейс и Express API. PostgreSQL запускается через Docker Compose с постоянным volume и доступен локально на `127.0.0.1:5433`. Пример `.env.example` содержит имена нужных переменных без рабочего ключа.

## Как запустить у себя

Нужны Node.js 24, npm и Docker Desktop. В корне проекта:

1. Скопируйте `.env.example` в `.env`, задайте свой `OPENROUTER_API_KEY` и замените демонстрационный `COOKIE_SECRET` длинным случайным значением. `.env` игнорируется Git.
2. Выполните `docker compose up -d db` и `npm ci`.
3. В двух терминалах выполните `npm run dev:api` и `npm run dev:web`.
4. Откройте `http://127.0.0.1:5173`.

## Что уже проверено

- Docker Compose поднимает PostgreSQL, healthcheck проходит; адрес БД совпадает с `DATABASE_URL` в примере окружения.
- Прошли `npm test --workspaces` (**24 теста API, 16 тестов интерфейса**), `npm run typecheck --workspaces` и `npm run build --workspaces`.
- Открываются страница и маршрут через Vite proxy; проверены выдача сессии, ошибка 400 для неверного запроса и ожидаемая 503 при пустом ключе.
- На собранном интерфейсе и реальном API/PostgreSQL пройден браузерный smoke с временным управляемым SSE upstream: первый фрагмент появился до `done`, после завершения показан полный ответ, история сохранилась после обновления страницы.
- Второй независимый cookie-клиент создал вторую пару; SQL подтвердил две строки с разными `session_id`. Временный сервер остановлен, обе тестовые строки удалены.

## Что проверить с реальным ключом

Отправьте запрос к настоящей модели и убедитесь, что текст появляется до завершения ответа. Обновите страницу и проверьте историю. Повторите запрос в новом окне инкогнито и убедитесь, что старая история не показана. Затем проверьте строки БД:

```powershell
docker compose exec db psql -U ai_gate -d ai_gate -c "SELECT session_id, prompt, answer, created_at FROM exchanges ORDER BY created_at;"
```

Локальный сценарий с управляемым потоком **пройден**. Повтор с настоящим OpenRouter **пока заблокирован**: локальный `OPENROUTER_API_KEY` пуст. Подробный порядок также есть в [quickstart](../specs/001-ai-gate-demo/quickstart.md).
