# 5. Публикация на Vercel

## Что получает проверяющий

Проверяющий открывает одну HTTPS-ссылку `*.vercel.app`, без регистрации задаёт вопрос и видит ответ по мере генерации. После завершения пара «запрос — ответ» появляется в истории текущей анонимной сессии. Завершённая пара также записывается в PostgreSQL.

## Какие слои подготовлены

- **Интерфейс (`apps/web`)** собирается в статические файлы. Его запросы к `/api/session` и `/api/chat` остаются на том же домене; логика формы и истории не меняется.
- **API (`apps/api`, корневой `api/`)** запускается как две Vercel Node Functions. Они используют существующее Express-приложение: cookie-сессию, OpenRouter SSE и запись результата. Локальный `server.ts` по-прежнему нужен только для запуска на компьютере.
- **База (`db/init.sql`)** создаётся в доступной Vercel PostgreSQL. Локальная Docker-база не переносится и остаётся для разработки.
- **Конфигурация (`vercel.json`)** задаёт сборку из корня монорепозитория и папку готового интерфейса `apps/web/dist`.

Браузер хранит свою историю в `localStorage` по ID сессии. История с `localhost` не появится на домене Vercel, потому что браузер разделяет данные разных адресов. Серверный маршрут чтения истории из БД в этот минимальный результат не входит.

## Что сделать в Vercel

1. Войти в Vercel через GitHub и импортировать репозиторий `Solio69/ai-gate` как **один проект**. Root Directory оставить корнем репозитория. Использовать личный бесплатный план **Hobby**. На экране настройки импорта пока не нажимать **Deploy**: сначала добавить переменные из шага 2.
2. В Environment Variables для **Production** добавить `COOKIE_SECRET` — длинную случайную строку, `OPENROUTER_API_KEY` — действующий ключ, и `OPENROUTER_MODEL=openrouter/free`. Секрет можно создать локально командой ниже и вставить только в Vercel:

   ```powershell
   node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
   ```

   Не добавляйте эти значения в Git, скриншоты или чат. `PORT` в Vercel не нужен. После добавления переменных нажать **Deploy** и дождаться первой сборки; до подключения базы `/api/chat` может вернуть 503.
3. В Storage/Marketplace этого проекта подключить **Neon PostgreSQL** на тарифе **Free** к окружению Production. При создании через Vercel отдельная ручная регистрация на сайте Neon не требуется. Убедиться, что интеграция добавила `DATABASE_URL` в переменные проекта; приложение ожидает именно это имя.
4. Из Storage открыть Neon SQL Editor и выполнить содержимое [`db/init.sql`](../db/init.sql) один раз. Там создаются таблица `exchanges` и индекс. Рабочую базу не использовать для автоматических интеграционных тестов: эти тесты пишут и удаляют строки.
5. После добавления базы и переменных запустить **новый Production deployment**: старый деплой не получает изменённое окружение автоматически. Использовать выданный адрес `*.vercel.app`; свой домен не требуется.

Все три сервиса имеют бесплатные лимиты: Vercel Hobby, Neon Free и OpenRouter Free. Бесплатный OpenRouter сейчас ограничен примерно 50 запросами в день; при достижении лимита возможна ошибка, а не успешный ответ. Платные тарифы и автопополнение для демонстрации не нужны. [Vercel Hobby](https://vercel.com/docs/plans/hobby), [Neon в Vercel](https://vercel.com/marketplace/neon), [OpenRouter Free](https://openrouter.ai/pricing/).

## Как проверить опубликованный результат

1. Открыть ссылку без входа в Vercel. В Network проверить `GET /api/session`: статус 200, ответ с `sessionId`, подписанная cookie с `HttpOnly` и `Secure` на HTTPS.
2. Отправить короткий запрос. В Network у `POST /api/chat` должен быть `text/event-stream`; `delta` приходит до `done`, а текст виден ещё до окончания генерации. Ключ OpenRouter не должен появляться в исходниках браузера и сетевых запросах браузера.
3. После `done` обновить страницу: пара остаётся в истории. В Neon SQL Editor выполнить:

   ```sql
   SELECT id, session_id, prompt, answer, created_at
   FROM exchanges
   ORDER BY created_at DESC
   LIMIT 5;
   ```

   Для одного успешного запроса должна появиться ровно одна новая строка с полными текстами и ID этой сессии.
4. Открыть ссылку в инкогнито: история обычного окна там не отображается. Отправить запрос в инкогнито и убедиться, что новая запись имеет другой `session_id`.
5. При сбое посмотреть Runtime Logs проекта Vercel и состояние базы в Storage. Не пересылать лог целиком, если он содержит секреты.

До фактического опубликованного прогона его результат в [журнале проверок](../specs/002-vercel-deployment/verification.md) должен оставаться `NotRun`. Локальные команды и отдельная проверка на компьютере описаны в [локальном запуске](04-local-run.md).
