# Фича 3. История запросов и ответов

**Состояние:** реализовано; интеграционные тесты и локальный сквозной сценарий пройдены с управляемым upstream. Изменение отображения карточек описано в [спецификации 003](../specs/003-history-collapse/spec.md).

## Что видит пользователь

Завершённые пары запрос–ответ появляются в истории и восстанавливаются после обновления страницы в той же анонимной сессии. Новая сессия видит свой список. Каждая карточка сначала показывает только заголовок запроса и кнопку «Развернуть» справа. После раскрытия видны полный ответ с Markdown-оформлением и дата; кнопка «Свернуть» снова скрывает их. Карточки раскрываются независимо. После обновления страницы пары остаются, а карточки снова свёрнуты. Ответ, завершившийся ошибкой, в историю успешных пар не попадает.

## Какие слои изменены

- **PostgreSQL:** таблица `exchanges` хранит ID пары, ID анонимной сессии, запрос, полный ответ и время записи. Индекс по `session_id`, `created_at` и `id` подготовлен для выборки записей одной сессии.
- **API:** после полного ответа провайдера сервер вставляет одну строку с ID из подписанной cookie и только затем отправляет событие `done`. При обрыве потока или ошибке БД успешное завершение не отправляется.
- **Браузер:** после `done` пара сохраняется в localStorage под ключом `ai-gate:history:<sessionId>`. Интерфейс читает этот список после обновления и игнорирует повреждённые локальные данные. Состояние раскрытия живёт только в интерфейсе; полный текст пары остаётся в localStorage и PostgreSQL. Серверного маршрута чтения истории в текущем объёме нет.

Правка сворачивания затрагивает только интерфейс истории и его тесты: схема базы, API и формат localStorage не меняются.

## Как проверено

Три интеграционных теста с настоящей PostgreSQL проверили запись двух разных сессий, отсутствие частичной записи и ошибку записи в БД. Контейнер БД запущен и проходит healthcheck на `127.0.0.1:5433`.

В локальном сквозном сценарии браузер сохранил завершённую пару в localStorage и восстановил её после обновления. Второй независимый cookie-клиент отправил запрос через тот же API; SQL показал **две строки с двумя разными `session_id`**. Для генерации использовался временный управляемый SSE upstream. После проверки обе строки удалены.

Повтор этого сценария с настоящими ответами OpenRouter **не выполнялся нами**; ключ для ручной проверки добавлен пользователем. После правки прошли 24 теста интерфейса, проверка типов и сборка. Результаты записаны в [журнале фичи 003](../specs/003-history-collapse/verification.md).

Чтобы вручную проверить вид истории, откройте два завершённых запроса: до нажатия видны только их заголовки и кнопки, раскрытие одной карточки не раскрывает другую, а после обновления страницы обе снова свёрнуты. Полный сценарий — в [quickstart фичи 003](../specs/003-history-collapse/quickstart.md).
